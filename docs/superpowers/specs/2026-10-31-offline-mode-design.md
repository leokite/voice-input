# voice-input オフラインモード 設計書

- 作成日: 2026-10-31
- 状態: ユーザー確認待ち
- 前提とする設計書: `2026-10-24-voice-input-design.md`（本体）、`2026-10-24-correction-hotkey-design.md`（用語集への登録）

## 1. 何を作るか、なぜ作るか

文字起こしを Soniox（クラウド）ではなく、Mac の中だけで行う「オフラインモード」を足す。設定画面で「Soniox」か「ローカル」を選ぶ。ローカルを選んだ間は、音声も文字も Mac の外へ出さない。

理由は 2 つある。

1. **音声を外部に送れない環境で使いたい。** 外部に音声を送れない制約がある。今の VoiceInput は録音を Soniox に送るので使えない。
2. **私用の Mac でも、Soniox が使えないときの代わりがほしい。**

主な利用の場は、音声を外部に送れない環境。ネットワークに繋がるかどうかではなく、「送らない」ことが要件になる。

## 2. 目標、目標外、避けたいこと

### 目標
- ローカルを選んだ間は、録音から文字の入力までを、通信なしで完結させる。
- 日本語、英語、日本語と英語が混ざった発話（ソフトウェア関係の用語を含む）を、実用になる精度で文字にする。
- 話し終えてから文字が入るまでの待ちを、短い発話（数秒）で 1〜2 秒以内に収める。
- 今の用語集、フィラー除去、履歴、貼り付けの動きは、そのまま使えるようにする。
- 文字起こしの部分を差し替えられる作りにして、後から別のエンジンを足せるようにする。

### 最初の版ではやらないこと
- Apple の SpeechAnalyzer を選べるようにすること（比較の結果は 4 に残す。必要になったら足す）。
- 話しながら文字が出る「リアルタイム」の挿入。ローカルは「話し終えてからまとめて」だけ。
- ネットワークの状態を見て、自動で Soniox とローカルを切り替えること。切り替えは設定画面の手動だけ。
- モデルの手動配置を手助けする画面。保存場所は固定にするので、手で置けば動く（案内の文章は書かない）。
- 複数のモデルから選べるようにすること。モデルは 1 種類に固定する。
- iPhone など、Mac 以外への対応。

### 避けたいこと（動いていても失敗とみなす）
- ローカルを選んでいるのに、音声や文字が外へ送られる。Soniox にも OpenAI にもつながない。
- ローカルを選んでいるのに、Soniox の API キーがないと録音できない。
- 無音の録音から、ありもしない文が入力される（4 を参照）。
- 初回の録音で、モデルの準備のために何十秒も待たされる。
- ローカルを選んでいない人（今の使い方）の動きが、少しでも変わる。

## 3. 前提と制約

- Apple Silicon の Mac。対象の Mac は macOS 26 以降（確認済み）。
- 今のアプリは macOS 14 以降向けにビルドしている（`project.yml`）。端末内AI（Foundation Models）は macOS 26 以降のときだけ使う作りになっている。ローカルモードも、必要なら同じように macOS 26 以降だけに限ってよい（私の判断。WhisperKit の最低 macOS が 14 以上かどうかは未確認）。
- モデルの導入に限って、最初の 1 回だけダウンロードしてよい（確認済み）。制限のあるネットワークで届くかどうかは分からない。
- 外部のライブラリやモデルを使うのに、導入に追加の承認は要らない（確認済み）。
- アプリはサンドボックスに入っていない（権限は音声入力のみ）。通信を権限で止めることはできないので、「通信しない」はコードの作りとテストで守る。
- `VoiceInputCore` は今、外部の依存を持たず、モデルなしでテストできる。この性質を保つ（WhisperKit を `VoiceInputCore` に入れない。別のターゲットに分ける）。

## 4. 調べた事実と試作の結果（2026-10-31 時点）

### 候補の比較

| 候補 | 結論 |
|---|---|
| **WhisperKit**（Whisper large-v3-turbo の Core ML 版、Argmax 製、MIT） | **採用。** |
| Apple SpeechAnalyzer（macOS 26 以降、日本語に対応） | 不採用。速いが、技術用語の混ざった文で劣り、用語集（`contextualStrings`）が効かなかった。 |
| Qwen3-ASR（MLX） | 試していない。日本語が良いという報告はあるが、1 台での自己計測で、導入のリスクが高い。 |

### 試作の結果

`Eval/` の音声 20 本（`say` による合成音声）を、使い捨ての試作で認識させた。M5 / 32GB。点数は `CharacterAccuracy`（1.0 が完全一致）。

| | Apple | WhisperKit | WhisperKit + 用語集 |
|---|---|---|---|
| 日本語のみ（5 本） | 0.986 | 0.986 | 0.986 |
| 英語のみ（5 本） | 0.972 | 0.972 | 0.972 |
| 技術用語の混在（10 本） | 0.663 | 0.817 | **0.851** |
| 全体 | 0.821 | 0.898 | **0.915** |
| 1 件の処理時間（音声は平均 3.3 秒） | 約 0.07 秒 | 約 0.5 秒 | 約 1.0 秒 |

その他に分かったこと。

- **モデルの大きさは 1.5GB。** 初回の起動（Core ML のコンパイルを含む）は約 97 秒。2 回目以降の準備は約 1.6 秒。
- **最大 RSS は約 242MB。** ただし Core ML と Neural Engine が使うメモリは含まれない可能性がある。実際の使用量は未確認。
- **完全な無音を渡すと、WhisperKit は文を作る。** 日本語指定で「ご視聴ありがとうございました」、英語指定で `Thank you.`。室内ノイズやファン音ぐらいのノイズだけの録音では、空の文字列が返った。
- **用語集のヒントは効く。** 初期プロンプトに用語を並べると、`Google Calendar` が原綴りで出るようになった。ただし処理時間が約 2 倍になった。
- `meeting` `Slack` `bug` `release` のような、日本語の読みに寄る英単語は、WhisperKit でもカタカナで出た。用語集の置き換え（`TextPipeline`）で直す。

### 試作の限界（この数字の読み方）
- 音声は合成音声で、20 本しかない。本物の声では差の出方が変わりうる。
- 「三時」と「3 時」の違いも減点になっている。実際の品質より少し低く出る。
- 言語は、日本語の文字を含むかどうかで「日本語」か「英語」を決めた。実際のアプリでは、言語のヒントで決める。
- Soniox との比較はしていない。
- 30 秒を超える長い発話は試していない。
- 試作のコードは残さない。再現するときは、WhisperKit v1.1.1、モデル `large-v3-v20240930_turbo`、temperature 0、用語集は「, 」でつないだ文字列を初期プロンプトにした、という条件を使う。

## 5. 使い方と動き

### 5.1 切り替え
設定画面に「文字起こし」の選択を足す。「Soniox」（既定）と「ローカル（オフライン）」。設定ファイル `settings.json` に保存する。値が無い古い設定ファイルは「Soniox」として読む。

### 5.2 ローカルを選んだときの動き
- 録音の開始、停止、キー、無音での自動停止、フィラーの除去、用語集の置き換え、履歴、貼り付けは、今と同じ。
- **文字の入れ方は常に「話し終えてからまとめて」。** ローカルのときは、設定画面で「文の区切りごと」を選べないようにする（選択済みでもローカルでは使わない。Soniox に戻せば元の設定が効く）。
- **Soniox の API キーは要らない。** キーがなくても録音できる。
- 録音の間は音声をためておく。止めたときにまとめて認識し、結果を今と同じ道で処理する。
- 認識の間、表示は今の「処理中」を使う。

### 5.3 モデルの導入
- 設定画面に、ローカルの状態を出す。「未導入」「ダウンロード中（進み具合）」「準備中」「使える」「失敗」。
- 「ダウンロード」を押したときだけ通信する。約 1.5GB であることを先に表示する。
- ダウンロードが終わったら、そのまま 1 回認識を動かして、Core ML のコンパイルを済ませる（初回の約 97 秒を、最初の音声入力で待たされないようにするため）。「準備中」の間は録音を受け付けない。
- 失敗したらその理由を表示し、やり直せるようにする。途中で止めても壊れた状態にならない。
- モデルを削除できるようにする（空きを増やすため）。
- 保存場所は `~/Library/Application Support/VoiceInput/Models/` の下に固定する。
- ローカルを選んでいてもモデルが「使える」状態でないときは、録音を始めず、設定画面を開いて理由を知らせる（API キーがないときと同じ扱い）。

### 5.4 無音のときは認識しない
音が一度も出なかった録音（RMS が、無音と判定するしきい値を一度も超えなかった録音）は、WhisperKit に渡さない。何も入力せず、履歴にも残さない。完全な無音に対する架空の文を防ぐため。しきい値は今の `SilenceDetector` と同じものを使い、別の値は増やさない（私の判断）。

### 5.5 言語
- 言語のヒント（`languageHints`）が 1 つなら、その言語で認識する。
- 複数（既定は `ja, en`）のときの決め方は、作る人に任せる（8 を参照）。試作では、日本語を含む文は `ja`、そうでない文は `en` と固定して測った。

### 5.6 用語集
- 用語集の用語を、認識の初期プロンプトとして渡す。今、Soniox に渡している並び（`contextTerms()`）を元にする。
- プロンプトには長さの上限がある。上限に収まるように、最近使った用語を優先して絞る。処理時間が増えるので、上限は短めにする（具体的な値は作る人が実測で決める）。
- 用語集の置き換え（読みが似た語の直し）は今のまま `TextPipeline` で行う。

### 5.7 直しの登録（用語集に登録するキー）
- ローカルのときは、OpenAI を使わない。組み合わせの取り出し（`extractor`）も、置き換え元探し（`locator`）も無効にする。OpenAI の設定がオンでも、API キーがあっても、使わない。
- 設定画面では、ローカルのとき OpenAI の項目を「オフラインモードでは使えません」の表示に変える（消さない。Soniox に戻せば元の設定が効く）。
- 置き換えの判断は、今と同じ端末内AI（Foundation Models）で行う。これは Mac の中だけで動くので、ローカルでも使う。使えない Mac では今と同じく「認識のヒントだけ」を登録する。

### 5.8 通信しないことの保証
- ローカルを選んでいる間、Soniox への接続も OpenAI への接続も作らない。
- モデルの読み込みは、保存場所のファイルだけから行う。ファイルがなければ、ダウンロードを試みず、5.3 の「使える状態でない」扱いにする。
- 通信が起こる唯一の操作は、設定画面の「ダウンロード」。

## 6. エラー時の動き

| 状況 | 動き |
|---|---|
| モデルが未導入、準備中、壊れている | 録音を始めない。設定画面を開いて理由を表示する |
| 認識が失敗した（モデルのエラーなど） | 画面に「文字起こしに失敗しました」を 3 秒出す。音声は捨てる。履歴には残さない |
| 認識に時間がかかる | 今の Soniox 向けの待ち時間（接続 5 秒、終了待ち 5 秒）をそのまま使わない。認識の長さに応じて待つ（具体的な値は作る人が決める） |
| メモリ不足で読み込めない | 失敗として表示する。Soniox に自動で切り替えない |
| ダウンロードの失敗 | 理由を表示し、やり直せる |

## 7. データの保存場所

- `settings.json`: 「文字起こし」の選択を足す。
- `~/Library/Application Support/VoiceInput/Models/`: WhisperKit のモデル（約 1.5GB）。
- 履歴、用語集、フィラーは今のまま。ローカルで書いた履歴も、Soniox の履歴と同じ形で同じ場所に入る。

## 8. 作る人に任せること

- 文字起こしの部分の差し込み方。今の仕組みは `TranscriptionSession`（`start / sendAudio / finalize / responses`）で、Soniox 向けに作られている。それをローカルでも使い回すか、新しい口を作るか。ただし、`SessionController` は Soniox の「確定トークン」と `<fin>` を前提にしているので、どちらにしても、ローカルの結果をその形に載せるか、口を変えるかを決める必要がある。
- WhisperKit を入れる場所。`VoiceInputCore` に入れず、別のターゲットに分ける（3）。`project.yml` と `Package.swift` の両方に関わる。
- WhisperKit の最低 macOS が、アプリの最低 macOS（14）より高いときの扱い（3 の判断を参照）。
- 複数の言語のヒントがあるときの決め方。たとえば、音声から言語を判定して、ヒントの中から選ぶ。試作で測った「日本語は `ja`、英語は `en`」が、判定でも出るかを `Eval/` で確かめる。
- 用語集のプロンプトの長さの上限（精度と処理時間の折り合い）。
- 30 秒を超える長い発話の扱い（分割して認識するか）。試作では試していない。
- 起動時にモデルを読み込んでおくか、最初の録音で読み込むか。1.5GB のモデルがメモリに載り続けることを許すか（私の勧めは、ローカルを選んでいるときだけ、起動時に裏で読み込んでおくこと）。
- 認識の待ち時間の値。
- 設定画面の見た目と文言。

## 9. 確かめ方

### 自動テストで確かめること
- 「Soniox」を選んだときの動きが変わらないこと（既存のテストがそのまま通る）。
- ローカルのとき、Soniox のセッションも OpenAI の部品も作られないこと。
- ローカルのとき、Soniox の API キーがなくても録音が始まること。
- 音が一度も出なかった録音は、認識に渡されず、何も入力されないこと。
- ローカルのとき、「文の区切りごと」の設定があっても一括で入ること。
- モデルが使える状態でないとき、録音が始まらないこと。
- 古い `settings.json`（文字起こしの値がない）を読むと「Soniox」になること。

認識そのもの（WhisperKit）は、偽物（テスト用の差し替え）で置き換えて試す。モデルはテストに含めない。

### 精度の測り方
`voice-eval` を、ローカルのエンジンでも動かせるようにする（Soniox の API キーは要らない）。`Eval/` の 20 本で、次を満たすことを確かめる（数字は試作の結果を元にした私の判断）。

- 日本語のみ、英語のみ: 各 0.97 以上
- 技術用語の混在（用語集あり）: 0.85 以上
- 全体: 0.91 以上

本体の設計書の「精度 95% 以上」は、Soniox の目標のまま。ローカルでは目標にしない（試作で届かなかったため）。本物の声での測定は、利用者が `Eval/` の音声を自分の声に差し替えて行う（手順は `Eval/README.md`）。

### 手で確かめること
- Wi-Fi と有線をすべて切った状態で、ローカルを選び、録音から入力まで動くこと。
- 通信を監視して（例: ネットワーク監視のツール）、ローカルを選んでいる間は VoiceInput が何も送っていないこと。ダウンロードの操作のときだけ通信が起こること。
- モデルの導入から最初の音声入力まで、待たされすぎないこと。
- 制限のあるネットワークで、ダウンロードが通るか。通らない場合の扱いを決める（モデルの手動配置は今回の目標外。通らなければ、次の版で扱う）。
- `docs/manual-checks.md` の確認表に、ローカルの項目を足す。

### 追加で残る不確かさ
- 実際のメモリ使用量。
- 本物の声での精度。
- 長い発話での挙動。
