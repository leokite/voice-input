# 直した単語を用語集に登録する機能 設計書

- 作成日: 2026-10-24
- 状態: ユーザー確認待ち
- 前提: `docs/superpowers/specs/2026-10-24-voice-input-design.md`（VoiceInput 本体の設計書）

## 1. 何を作るか、なぜ作るか

音声入力の後に、誤認識された単語をユーザーが手で直したとき、その直しを VoiceInput の用語集に登録する機能。直した部分を選んでショートカットキーを押すだけで登録される。

用語集は「使うほど精度が上がる」仕組みの中心だが、今は履歴画面から手で登録するしかない。直したその場で、手間なく登録できるようにする。

## 2. ユーザーが決めたこと

- **キーを押す方式にする**: 「直したら自動で気づく」方式は、ユーザーが使うアプリ（ターミナル、ブラウザ上の Notion・Gmail・Claude、VS Code）では入力欄の中身を読めないことが多い。そのため、キーを 1 回押す手間が増えても、どのアプリでも確実に動く方式を選んだ。
- **確認画面は出さない**: キーを押したらすぐに登録し、「Docker を登録しました」のような短い表示を出す。
- **普通の言葉が誤認識された場合**: 置き換え元が普通の言葉（例:「どうか」）のときは、置き換え（どうか → Docker）は登録しない。認識のヒント（Docker）だけを登録する。本当に「どうか」と言いたいときに Docker に変わってしまうのを防ぐため。
- **AI は Apple の端末内AI（Foundation Models）だけを使う**: Claude Haiku などの外部 API は使わない。別の API キーも費用も要らず、文字が外部に出ない。

## 3. 目標、目標外、避けたいこと

### 目標
- ターミナル、Chrome / Safari 上の Notion・Gmail・Claude、VS Code で動く。
- キーを押してから表示が出るまでを、2 秒以内にする（目標値は私の判断）。

### 目標外
- 直したことを自動で検知する機能
- 外部の AI サービスを使うこと
- 音声入力していない文字を、新しい用語として登録すること（履歴の中にない語は扱わない）

### 避けたいこと
- 普通の言葉が置き換えに登録され、別の場面で勝手に書き換わる。
- キーを押したことで、ユーザーのクリップボードの中身が変わる。
- キーを押したことで、手前のアプリに文字が入ったり、選択が外れたりする。

## 4. 前提と制約

- VoiceInput 本体と同じ前提: macOS 14 以降、Apple Silicon、Swift 6、Xcode 27.1、App Sandbox なし。
- **Foundation Models** は macOS 26 以降で使える（`import FoundationModels`、`SystemLanguageModel.default`）。2026-10-24 にこの Mac（macOS 26.6.2）で確かめた結果:
  - `availability` は `available`。
  - `supportedLanguages` に日本語が含まれる。
  - 自由な文章で質問すると、単語ではなく文全体で答えが返ってきた。単語の組み合わせをそのまま取り出す役には向かない。
- そこで、**直した箇所の特定はプログラムで確実に行い、AI には判断だけを任せる**（私の判断）。
- macOS 25 以前の Mac や、Apple Intelligence がオフの Mac では AI を使えない。その場合は、AI を使わない動き（7.3 章）にする。
- `availability` が `unavailable` のときの理由: `deviceNotEligible`（非対応の機種）、`appleIntelligenceNotEnabled`（Apple Intelligence がオフ）、`modelNotReady`（モデルを準備中）。

## 5. 使い方

1. 音声入力をする（例:「どうかコンテナを再起動してから API を確認します。」と入る）。
2. 手前のアプリで、誤認識された部分を直す（「どうか」を「Docker」に打ち直す）。
3. 直した部分を選ぶ。単語だけでも、前後を含む範囲でもよい（例:「Docker」、または「Dockerコンテナを再起動」）。
4. 登録キー（初期値 ⌃⌥D）を押す。
5. 画面下部中央に「Docker を登録しました」と 3 秒間表示される。
6. 表示が出ている 3 秒の間にもう一度登録キーを押すと、その登録を取り消して「登録を取り消しました」と表示する。

## 6. キー

- 初期値は ⌃⌥D（Control + Option + D）。D は Dictionary の頭文字（私の判断）。
- 設定画面で変えられる。修飾キー（⌃⌥⌘⇧ のどれか 1 つ以上）と、普通のキー 1 つの組み合わせにする。修飾キーなしの組み合わせは選べない（普段の入力を邪魔しないため）。
- キーの監視には、既存のキー監視（CGEventTap、専用スレッド）を使う。登録キーの keyDown と keyUp は握りつぶし、手前のアプリには届けない。
- 録音中や、文字を入れる処理の最中に押された場合は、何もせず「処理中です」と表示する。「処理中」とは、録音セッションの状態が待機中（idle）以外のとき（私の判断）。ただし、取り消しの判定（7.5 章）は処理中の判定より先に行う。そのため、取り消しの 3 秒の間に録音を始めていても、取り消しはできる。
- 設定には新しい項目（例: `glossaryShortcut`、修飾キーの集合と keyCode）を足す。古い設定ファイルにこの項目がない場合は、初期値の ⌃⌥D を使う（私の判断）。
- 既存の録音キー（修飾キーだけ、または F13〜F19 を単独で押すキー）とは別の経路で判定する。録音キーと同じ keyCode を使う組み合わせは選べないようにする（私の判断）。

## 7. 処理の流れ

### 7.1 選ばれた文字を読む

1. **アクセシビリティで聞く**: 手前のアプリでフォーカスされている要素に、選択中の文字（`kAXSelectedTextAttribute`）を問い合わせる。空でない文字が返ってきたら、それを使う。
2. **空なら ⌘C を送る**: クリップボードの中身を保存してから、手前のアプリに ⌘C を送る。⌘C のイベントには、修飾キーとして ⌘ だけを明示して付ける（私の判断）。登録キーの ⌃⌥ がまだ押されたままでも、⌃⌥⌘C にならないようにするため。クリップボードが変わるのを最大 0.3 秒待って、中身を読む。読み終わったら、必ず元の中身に戻す（文字を入れるときと同じ `PasteboardSnapshot` を使う）。送る ⌘C には、文字を入れるときと同じ印（`eventSourceUserData`）を付け、自分のキー監視が反応しないようにする。
3. 0.3 秒たってもクリップボードが変わらなかったら、「文字を選んでからキーを押してください」と表示して終わる。
4. 読んだ文字が 200 文字を超えたら、「選んだ範囲が長すぎます」と表示して終わる（私の判断）。
5. パスワード入力中（Secure Event Input がオン）は、文字を読まずに「パスワード入力中は使えません」と表示する。

注意: VS Code では、何も選ばずに ⌘C を押すと、カーソルのある行全体がコピーされる。その場合は行全体を「選ばれた文字」として扱い、そのまま次へ進む。ターミナルで何も選ばずに押した場合は、クリップボードが変わらないので、3 の表示で終わる。

### 7.2 直した箇所を見つける（プログラムで行う）

1. 比べる相手は履歴の新しい順に最大 5 件で、そのうち 10 分以内のものに限る（私の判断）。比べるのは履歴の `text`（実際に入れた、整えた後の文字列）で、`rawText` は使わない。ユーザーが直したのは入れた文字列のほうだからである。`inserted` が false の履歴（入れずに履歴にだけ残したもの）も対象に含める。履歴からコピーして貼り付けた後に直すこともあるため（私の判断）。
2. 選ばれた文字と各履歴を比べて、次のどちらに当てはまるかを調べる。
   - **前後を含む範囲が選ばれた場合**: 選ばれた文字と、履歴の一部が、文字単位でよく似ている。似ているかどうかは、選ばれた文字と、履歴の中でいちばんよく一致する部分を比べて決める（共通の文字数が、選ばれた文字の長さの 50% 以上）。複数の履歴が当てはまる場合は、共通の割合がいちばん高いものを使い、同じなら新しいものを使う。この場合は、両者の差分（違っている部分）を取り出す。差分が 1〜3 か所で、それぞれ 1〜30 文字のものだけを候補にする。
   - **単語だけが選ばれた場合**: 選ばれた文字が 30 文字以下で、履歴にそのまま含まれていない。この場合、どの部分が直されたのかはプログラムだけでは決められない。AI に、履歴の中のどの語が直されたものかを選ばせる（7.3 章）。比べる履歴は、10 分以内でいちばん新しいもの 1 件だけにする（私の判断）。直すのはたいてい直前の音声入力だからである。
3. どの履歴にも当てはまらなければ、「登録できる直しが見つかりませんでした」と表示して終わる。
4. 選ばれた文字が履歴とまったく同じ（直していない）場合も、同じ表示で終わる。

### 7.3 AI に判断させる

AI には、次の 2 つの判断だけを任せる。答えは Foundation Models の構造化出力（`@Generable`）で受け取り、自由な文章は使わない。

1. **単語だけが選ばれた場合に、置き換え元を選ぶ**: 履歴の文と選ばれた語を渡す。AI は、履歴の文の中から、その語に直されたと考えられる部分をそのまま抜き出して答える。答えが履歴の文に含まれていなければ、AI の答えは使わない。
2. **置き換え元が普通の言葉かどうかを判断する**: 例えば「どうか」「メイン」「ログ」は普通の言葉（true）、「キューバーニーツ」「ぎっとはぶ」は普通の言葉ではない（false）。

AI を使えない場合（4 章の条件）:
- 前後を含む範囲が選ばれた場合は、差分で見つけた組み合わせを使う。普通の言葉かどうかは判断できないので、すべて普通の言葉として扱う。つまり、認識のヒントだけを登録する。
- 単語だけが選ばれた場合は、置き換え元を決められない。選ばれた語を認識のヒントとしてだけ登録する。
- AI が使えない理由は、設定画面に 1 行で表示する（例:「Apple Intelligence がオフのため、置き換えは登録されません」）。

AI の呼び出しが 1.5 秒以内に終わらない場合や、エラーになった場合も、AI を使えないときと同じ扱いにする（私の判断）。

### 7.4 登録する

見つかった組み合わせ（置き換え元 → 正しい語）ごとに、次のように登録する。

- 正しい語は、必ず認識のヒント（`Glossary.terms`）に足す。すでにあれば足さない。
- 置き換え元が普通の言葉でない場合だけ、置き換え（`Glossary.replacements`）を足す（既存の `addCorrection` を使う）。
- 置き換え元と正しい語が同じ、または置き換え元が空の組み合わせは捨てる。
- 正しい語が、空白や句読点だけの組み合わせも捨てる。置き換え元と正しい語の両方が 1 文字だけの組み合わせ（「の」→「へ」のような助詞の直しなど）も捨てる。用語にするほどの語ではないため（私の判断）。
- 1 回のキー操作で複数の組み合わせが見つかった場合は、それぞれを別の用語・置き換えとして登録する。
- 登録した内容（足した用語と置き換え）を、取り消し用に覚えておく。

表示:
- 置き換えも登録した場合: 「どうか → Docker を登録しました」
- ヒントだけを登録した場合: 「Docker を登録しました」
- 複数ある場合: 「Docker ほか 1 件を登録しました」

### 7.5 取り消す

- 登録の表示が出ている 3 秒の間に、もう一度登録キーを押すと取り消す。
- 取り消しでは、その登録で足した用語と置き換えだけを消す。もともとあったものは消さない。
- 3 秒を過ぎた登録は、用語集の画面から手で消す。
- 取り消せるのは、直前の 1 回の登録だけ。取り消し用の記録はメモリにだけ持ち、ファイルには保存しない（私の判断）。
- 3 秒の間にユーザーが用語集の画面で同じ項目を消していた場合は、残っているものだけを消す。

## 8. 作る人に任せること

- 差分を取る方法（文字単位の最長共通部分列など）と、細かいしきい値の調整（上の値は目安）
- AI に渡す指示文の書き方と、`@Generable` の型の形
- ファイルの分け方。判定のロジック（選んだ文字と履歴の比較、登録の規則、取り消し）は VoiceInputCore に置いてテストする。キー操作から登録までの流れは AppCoordinator が受け持つ（私の判断）。
- Foundation Models の組み込み方。動作環境は macOS 14 以降のまま変えない。`#if canImport(FoundationModels)` と `if #available(macOS 26, *)` で、使える Mac でだけ使う。AI はプロトコルの後ろに置き、テストでは偽物に差し替える（私の判断）。
- 設定画面での登録キーの選び方の見た目

## 9. 確かめ方

### 自動テスト
- 差分の取り出し（日本語、英語、混在、1 か所と複数か所、差分なし、まったく違う文）
- 履歴の選び方（5 件、10 分以内の制限、いちばん似ている履歴を選ぶこと）
- 登録の規則（普通の言葉ならヒントだけ、重複は足さない、取り消しで足した分だけ消える）
- AI を使えないときの扱い（偽物の AI で、使えない、時間切れ、答えが履歴にない、の各場合）

### 手で確かめること
- ターミナル、Chrome の Notion・Gmail・Claude、Safari、VS Code で、単語だけを選んだ場合と、前後を含めて選んだ場合の両方で登録できる。
- キーを押した後もクリップボードの中身が変わらず、手前のアプリの選択も外れない。
- 「どうか → Docker」のような普通の言葉の誤認識では、置き換えが登録されず、ヒントだけが登録される。
- 登録した後に同じ言葉を話すと、正しく認識される。
