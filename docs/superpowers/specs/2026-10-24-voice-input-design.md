# voice-input 設計書

- 作成日: 2026-10-24
- 状態: ユーザー確認待ち

## 1. 何を作るか、なぜ作るか

Apple Silicon の Mac で動く、自分専用の音声入力アプリ。キーを押して話すと、どのアプリのどの入力欄でも、カーソル位置に文字が入る。

Wispr Flow のような市販の音声入力アプリは月 15 ドル前後かかる。たくさん使いたいので、固定の月額は払いたくない。使った分だけ払う、安い従量課金の認識エンジン（Soniox）を使い、自分でアプリを作る。

## 2. 必須の条件（ユーザーの要望）

1. **精度がとても高い**: 目標は 95% 以上。日本語、英語、日本語と英語が混ざった発話に対応する。
2. **速い**: 話し終えたら、すぐに文字が出る。
3. **専門用語に強い**: 主にソフトウェア関係の用語。自分用の用語集を持ち、使うほど精度が上がっていく。
4. **安い**: たくさん使っても費用が気にならない。
5. **どこでも使える**: どのアプリ、どの画面の入力欄でも使える。
6. **フィラーを消す**: 「あー」「えー」などは自動で取り除く。

## 3. 目標、目標外、避けたいこと

### 目標
- 上の必須の条件をすべて満たす。
- 話し終えてキーを離してから、文字が入りきるまでを 1 秒以内にする（目標値の 1 秒は私の判断）。

### 最初の版ではやらないこと
- AI（LLM）による文章の書き直し、言い直しの整理、要約、翻訳
- オフライン（ネットなし）での認識
- 他のアプリ上で直した内容を自動で読み取って学習すること
- App Store などでの配布、複数ユーザーへの対応、Mac 以外への対応

### 避けたいこと（動いていても失敗とみなす）
- 普段のキー入力を邪魔する。例えば、右 Option を使った普通の操作で録音が始まってしまう。
- 文字を入れるときに、ユーザーのクリップボードの中身が消える、または書き換わる。
- 入力中のアプリからフォーカスを奪う（表示を出したことでカーソルが外れる）。
- 録音していない間も Soniox との接続が開いたままで、課金が続く。
- 意図しない場所に文字が入る。

## 4. 前提と制約

- **対象**: Apple Silicon の Mac。macOS 14 以降を対象にする（私の判断）。開発機は macOS 26.6.2。
- **言語**: Swift（ユーザーがお任せと回答）。UI は SwiftUI と AppKit を組み合わせる。
- **開発環境**: この Mac には Xcode 本体が入っておらず、Command Line Tools（Swift 6.3.3）だけがある。そこで Swift Package Manager でビルドし、スクリプトで `.app` の形にまとめて署名する（私の判断）。
  - マイクやアクセシビリティの許可は、アプリの署名に結びついて保存される。その場限りの署名（ad-hoc 署名）だとビルドのたびに許可が外れることがあるため、自己署名の証明書を作り、毎回同じ証明書で署名することを推奨する。
  - あとで Xcode を入れて Xcode プロジェクトに移す選択肢も残す。
- **認識エンジン**: Soniox のリアルタイム API（WebSocket）。API キーはユーザーが自分で用意する。
- **利用者**: ユーザー本人だけ。

## 5. Soniox について調べた事実（2026-10-24 時点）

| 項目 | 内容 |
|---|---|
| 料金 | リアルタイム認識は 1 時間あたり 0.12 ドル（ファイル認識は 0.10 ドル）。従量課金。1 日 2 時間使っても月に約 7 ドル、1 日 30 分なら月に約 2 ドル。 |
| 課金の単位 | **接続している時間の全体**に課金される（音声を送っていない時間も含む）。録音のたびに接続し、終わったらすぐ閉じる必要がある。 |
| モデル | `stt-rt-v5` |
| 接続先 | `wss://stt-rt.soniox.com/transcribe-websocket`。認証は接続時に `Authorization: Bearer <API_KEY>` ヘッダーで行う。 |
| 最初に送る設定 | `model`、`audio_format`（例 `pcm_s16le`）、`sample_rate`、`num_channels`、`language_hints`（例 `["ja","en"]`）、`language_hints_strict`、`context`、`enable_endpoint_detection` など |
| 結果の受け取り方 | 結果は単語（トークン）ごとに届き、それぞれ `text` と `is_final` を持つ。`is_final: false` は仮の結果で、後で変わることがある。`is_final: true` は確定した結果で、一度しか送られてこない。 |
| 確定させる | `{"type":"finalize"}` を送ると、それまでの音声がすべて確定する。完了すると `{"text":"<fin>","is_final":true}` が届く。話し終えてから約 200ms 後に送るのが推奨。早すぎると精度が落ちる。確定の指示を短い間隔で何度も送ると、接続が切れることがある。 |
| 終わらせる | 空の**テキスト**フレーム（`""`）を送る。サーバーは `finished: true` を返して接続を閉じる。空のバイナリフレームでは終わらない。 |
| 接続を保つ | 音声を送らない時間が続くときは、40 秒以内ごとに keepalive を送る。メッセージの正確な形は実装時に公式ドキュメントで確認する（おそらく `{"type":"keepalive"}`）。 |
| 用語のヒント | `context` で渡す。`general`（`{key, value}` の配列。10 組程度まで）、`text`（背景となる長めの文章）、`terms`（専門用語の文字列の配列）。合計の上限は約 8,000 トークン（約 1 万文字）で、超えると `invalid_request` エラーになる。 |
| 精度 | Soniox 自身の公表値では、日本語の単語誤り率は 1.25%（OpenAI は 3.24%）。第三者による検証は見つからなかった。 |
| 速さ | 単語ごとに逐次結果が返る、という説明のみ。ミリ秒単位の公表値は見つからなかった。 |
| フィラー | Soniox がフィラーを消すかどうか、消す設定があるかどうかは、ドキュメントで確認できなかった。そのため、アプリ側で消す処理を必ず入れる。 |
| エラー | 401 `unauthenticated`、402 残高不足・月の予算超過、408 タイムアウト、429 同時接続数の上限、500 / 503 サーバーエラー など |

## 6. 使い方と動き

### 6.1 アプリの形
- メニューバーに常駐する。Dock にはアイコンを出さない。
- メニューの項目: 録音の開始と停止、履歴、用語集、設定、終了。

### 6.2 録音の開始と終了
2 つのモードがある。

- **切り替えモード**: キーを 1 回押すと録音が始まり、もう 1 回押すと終わる。
- **押している間だけモード**: キーを押している間だけ録音し、離すと終わる。

**初期設定のキーは右 Option（Alt）**。ユーザーの指示は「デフォルトは右 Alt」。2 つのモードの区別は次のとおりにする（私の判断）。

- 右 Option を短く押して離した場合（初期値は 300ms 未満）: 切り替えモードとして扱う。録音を始め、もう一度短く押すと止める。
- 右 Option を押し続けた場合（300ms 以上）: 押している間だけモードとして扱う。録音は押した瞬間から始め、離したら止める。
- 右 Option を押している間に別のキーが押された場合: 普通のキー操作とみなし、録音を取り消す。音声は送らず、文字も入れない。
- 押した瞬間に始めるのは、マイクの音声をアプリ内にためることだけにする。Soniox への接続と下部中央の表示は、録音だと確定した時点で始める（私の判断）。確定するのは、押し続けて 300ms を超えたとき、または短く押して離したとき。普通の Option 操作のたびに、課金される接続や表示のちらつきが起きないようにするため。ためておいた音声は、接続できたらまとめて送るので、冒頭の言葉は落ちない。
- 切り替えモードの止め忘れ対策として、無音が 60 秒続いたら自動で止める（私の判断。秒数は設定で変えられる）。無音かどうかは、アプリ内で音の大きさから判断する。
- 2 つのモードには、設定でそれぞれ別のキーを割り当てられる。修飾キーだけ（右 Option、右 Command、右 Control、Fn など）も選べるようにする。
- 補足: 日本語配列（JIS）の MacBook のキーボードには右 Option がない。その場合は設定で別のキーに変える。

### 6.3 録音中の表示
- 画面の下部中央に、小さな表示を出す。
- 状態は「録音中」「変換中」「エラー」の 3 つ。何もしていないときは表示を消す。
- 録音中は、音の大きさに合わせて動く簡単な表示を付ける（私の判断）。マイクが音を拾っていることが分かるようにするため。
- 表示がフォーカスを奪ってはいけない。クリックしても入力中のアプリからカーソルが外れないようにする（AppKit の非アクティブなパネルを使う）。
- マウスカーソルがある画面に表示する（私の判断）。

### 6.4 文字の入れ方
文字の出し方は 2 通り用意し、設定で切り替えられるようにする。どちらがよいかはユーザーが使ってみて決める。

- **まとめて入れる（初期設定。初期設定にしたのは私の判断）**: 録音が終わり、すべての結果が確定したら、整えた全文を一度にカーソル位置へ入れる。
- **リアルタイムで入れる**: 確定した部分を、確定するたびに入れていく。仮の結果は入力欄には入れない（後で書き換わることがあるため）。仮の結果は、下部中央の表示の中にプレビューとして見せる（私の判断）。
  - 確定した単語をそのまま 1 つずつ入れるのではなく、文の区切り（句読点）が来るまで、または確定が 0.5 秒ほど途切れるまでためてから入れる（私の判断）。フィラーや置き換え元の言葉が途中で分かれて、片方だけ入ってしまうのを防ぐため。それでも取りこぼしたフィラーや置き換えは、そのまま受け入れる。入れた後の文字は直さない。
  - 押している間だけモードでは、右 Option が押されたまま文字を入れることになる。送り込むキー入力や貼り付けに Option が混ざらないようにすること。

**文字を入れる先（私の判断）**
- 録音を始めたときに最前面にあったアプリを覚えておく。文字を入れる時点で最前面のアプリが変わっていたら、文字は入れずに履歴にだけ残し、表示で「履歴に保存しました」と知らせる。同じアプリの中で入力欄を移った場合は、そのとき入力中の欄に入れる。

文字の入れ方の条件:
- ユーザーのクリップボードを壊さない。クリップボード経由で貼り付ける方式を使う場合は、元の中身を退避し、貼り付けた後に戻す。
- 日本語入力（IME）が有効になっていても、そのまま正しく文字が入ること。
- パスワード入力欄のように、文字を送り込めない入力欄では何もしない。そのときは表示でユーザーに知らせる。
- 具体的な方式（クリップボード経由で貼り付ける方式、キー入力を送り込む方式など）は作る人が決めてよい。上の条件を満たすこと、そしてアプリごとに確認した結果を記録すること。

### 6.5 Soniox とのやり取り
- 録音を始めた瞬間に、マイクの音声をアプリ内にためはじめる。それと同時に WebSocket で接続する。つながったら、ためていた音声をまとめて送り、その後は届く音声を順に送る。接続を待つ時間に話した冒頭の言葉を落とさないため。
- 音声の形式: 16kHz、モノラル、`pcm_s16le`（私の判断）。
- 設定の例:
  ```json
  {
    "model": "stt-rt-v5",
    "audio_format": "pcm_s16le",
    "sample_rate": 16000,
    "num_channels": 1,
    "language_hints": ["ja", "en"],
    "enable_endpoint_detection": false,
    "context": {
      "general": [{"key": "domain", "value": "ソフトウェア開発"}],
      "terms": ["<用語集の単語>"]
    }
  }
  ```
- 録音を止めたら、約 200ms 待ってから `{"type":"finalize"}` を送る。`<fin>` が届いたら空のテキストフレームを送り、接続を閉じる。
- 録音のたびに接続し、終わったらすぐ閉じる（課金を抑えるため）。
- 録音の長さに上限は設けない。ただし、Soniox の 1 回の接続の上限（300 分）には注意する。
- 届いた `<fin>` などの特別な印は、文字としては入れない。

### 6.6 フィラーの除去
- 確定した結果に対して、アプリの中でフィラーの一覧と照らし合わせて消す。AI は使わない（速さと費用を保つため）。
- 初期の一覧は、ほぼ必ずフィラーとして使われる語にする（私の判断）。
  - 日本語: えー、えーと、えっと、あー、あのー、うーん、んー
  - 英語: um, uh, uhm, er, erm, hmm
- 「あの」「まあ」「その」のように、普通の言葉としても使われる語は初期の一覧に入れない。ユーザーが設定で足したり外したりできるようにする。
- 消した後に残る余計な読点やスペースも整える。例えば「えー、これは」は「これは」に、「um, I think」は「I think」にする。
- 句読点は Soniox が付けたものをそのまま使う。

### 6.7 用語集（使うほど精度が上がる仕組み）
用語集には 2 種類の登録がある。

1. **認識のヒント（terms）**: 「Kubernetes」「useEffect」など。Soniox の `context.terms` に毎回渡す。
2. **表記の置き換え**: 「ぎっとはぶ」を「GitHub」に、のように、認識結果の中の特定の文字列を別の表記に直す。フィラーを消した後に適用する。置き換え先の単語は、認識のヒントにも自動で加える。

「使うほど精度が上がる」流れ:
- 履歴画面で過去の文字起こしを見て、誤認識した箇所を選び、正しい表記を入れるだけで用語集に登録できる。選んだ箇所を置き換え元、入れた表記を置き換え先として登録する。
- 用語集の画面でも、単語を直接足したり、直したり、消したりできる。
- Soniox の `context` の上限（約 1 万文字）を超えないようにする。超えそうなときは、最近使われた単語を優先して渡し、ユーザーに知らせる（私の判断）。

### 6.8 履歴
- 最近の文字起こしを保存し、一覧で見られるようにする。保存件数の初期値は 200 件（私の判断）。
- 各項目に残す内容: 日時、整えた後の文字列、Soniox から届いたそのままの文字列、録音の長さ。
- 履歴から文字列をコピーできる。
- 文字を入れるのに失敗したときでも、結果は履歴に残す。後からコピーできるようにするため。
- 音声そのものは保存しない（私の判断）。

### 6.9 設定
- Soniox の API キー（macOS のキーチェーンに保存する）
- 2 つのモードそれぞれのキー
- 短く押したか、押し続けたかを分ける時間（初期値は 300ms）
- 文字の入れ方（まとめて入れる、リアルタイムで入れる）
- 言語のヒント（初期値は `["ja","en"]`）
- フィラーの一覧
- ログイン時に自動で起動するかどうか

### 6.10 初回起動
- マイクの許可と、アクセシビリティ（または入力監視）の許可を求める。足りない許可は、どこで何をオンにすればよいかを画面で案内する。
- API キーが未設定なら、設定画面を開く。

## 7. エラー時の動き

| 状況 | 動き |
|---|---|
| ネットにつながらない、接続に失敗した | 下部中央の表示に「エラー」を出し、短い理由を見せる。文字は入れない。 |
| 途中で接続が切れた | それまでに確定した部分は履歴に残す。録音を始めたときと同じアプリが最前面にあれば、確定した部分を入れる（私の判断）。表示でエラーを知らせる。 |
| API キーが間違っている（401） | エラーを表示し、設定画面へ案内する。 |
| 残高不足、予算超過（402） | エラーを表示し、Soniox の管理画面で確認するよう案内する。 |
| マイクの許可がない | 録音を始めず、許可の出し方を案内する。 |
| 何も話されなかった | 何も入れずに終わる。 |

## 8. データの保存場所
- 用語集、フィラーの一覧、設定、履歴は `~/Library/Application Support/VoiceInput/` に JSON で保存する（私の判断）。
- API キーだけはキーチェーンに保存する。

## 9. 確かめ方

### 自動テストで確かめること
- フィラーの除去（日本語、英語、混在。読点やスペースの整え方も含む）
- 表記の置き換え
- キーの判定（短く押す、押し続ける、他のキーと一緒に押す、の区別）
- Soniox から届いた結果の組み立て（確定と仮の扱い、`<fin>` の扱い）
- `context` の上限を超えないように削る処理

### 手で確かめること
- 少なくとも次のアプリで文字が正しく入ること: テキストエディット、メモ、Safari と Chrome の入力欄、Slack、VS Code、ターミナル
- 日本語入力が有効な状態でも正しく入ること
- クリップボードの中身が変わらないこと
- 録音を止めてから文字が入るまでの時間（目標は 1 秒以内）
- ソフトウェア用語を多く含む文で、用語集に登録する前と後の精度を比べる

### 精度の測り方（私の判断）
- 日本語、英語、混在、ソフトウェア用語入りの例文を 20 文ほど用意する。ユーザーが読み上げて録音し、正解の文と比べて文字単位の正解率を出す。この評価をくり返し実行できるようにする。
- 95% は目標値として扱う。下回っても、それだけで不合格にはしない。用語集やヒントの改善に使う。

## 10. 作る人に任せること
- アプリ内部の構成、クラスやファイルの分け方
- 文字を入れる具体的な方式（6.4 の条件を満たすこと）
- 全体のキー入力の監視方法（CGEventTap など）
- マイク音声の取り込みと変換の方法
- 各画面の見た目の細部
- `.app` にまとめて署名するスクリプトの作り方
